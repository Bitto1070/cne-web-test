# What is the Global Script?

The **Global Script** is the first file of your mod to run, and stays loaded for as long as your mod is active. It's useful for running functions on every state, or for setup that needs to happen before anything else in the mod.

You can make a global script by adding `global.hx` to your `data` folder.

For most mods, you'll mostly only need `new()` for setup, `destroy()` for resetting and `update()` for any extra key combinations that you'd need to use on any state.

# Global Variables and Functions
You can use the global script to store functions that are needed in a lot of states, or variables that need to be remembered between them. The easiest way to do this is by making them `static`:
<div style="display: grid; justify-content: left;">
```haxe
// global.hx
static var tickets = 0; // Tickets need to be remembered to be spent later

static function giveTickets(amount:Int) {
	tickets += amount;
	trace('You now have ' + tickets + ' tickets.');
}
```
```haxe
// Then, in a different script...

function create() {
	trace(tickets); // 0
	giveTickets(10); // You now have 10 tickets.
	trace(tickets); // 10
}
```
</div>

However, it's recommended to instead have less used functions as a [custom class](./classes) to import only when needed to save on memory.


# Reloading the Global Script

You can reload global scripts by holding `Shift` and pressing the `Reload State` keybind. By default, this is `Shift` + `F5`.<br/>
Doing this will destroy and re-initialize the global script, so you need to ensure you properly destroy or remove things once the script is no longer active, to prevent issues with other mods or addons.
<div style="display: grid; justify-content: left;">
```haxe
function destroy() {
/*
	In here, you'd reset things that would persist to other mods, breaking them in the process:
	- Resize the window back to 1280x720 (ex. 4:3 mods);
	- Unload custom cursors;
	- Reset the framerate counter;
	- etc.
*/
}
```
</div>
However, this does not reset any `static` variables, so to make sure that your mod does not break when being reloaded, it's recommended that you reset any static variables to their original value, if needed.
<div style="display: grid; justify-content: left;">
```haxe
static var exampleCounter = 0; // Elsewhere, this counter would be incremented.

function new() {
	exampleCounter = 0; // Reloading the global script now resets the counter.
}
```

Reloading via rechoosing the mod from the mod switch menu does clear static variables, so if anything breaks from them not being reset, do that instead.

</div>

# Multiple Global Scripts

You can have multiple global scripts by importing them inside `global.hx`:
<div style="display: grid; justify-content: left;">
```haxe
importScript("data/utils"); // Doing this inside global.hx would turn utils.hx into a second global script
```
</div>
Anything you put in these scripts will function as a global script, and will be accessible by other global scripts if set to `public` or `static`.

This is mostly only useful for organization purposes, but may make global script creation easier.

Note: this is the only time where making something `public` does something, as scripts from outside the global scripts pack can't access them unless they're `static`.
